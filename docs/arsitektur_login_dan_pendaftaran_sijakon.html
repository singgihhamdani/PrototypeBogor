Tata Kelola Akun Kedinasan (Mengapa Opsi A?)

Prinsip pendaftaran tertutup berbasis penugasan resmi SK Bupati / Kadis PUPR

Regulasi Akuntabel

Aplikasi SIJAKON Kabupaten Bogor mengelola dokumen hukum konstruksi yang sensitif, seperti Berita Acara Pemeriksaan (BAP SIMAK Pilar 1–3), Surat Rekomendasi Sanksi, sertifikasi TKK, serta data keuangan kontrak paket APBD OPD. Oleh karena itu, skema pendaftaran publik terbuka (self-registration) ditutup demi alasan integritas. Sistem mengadopsi Opsi A (Admin-Invited Registration) dengan landasan berikut:

🛡️ 1. Proteksi Dokumen Hukum & Zero Spam

Mencegah pendaftaran akun anonim atau pihak luar yang tidak memiliki legitimasi hukum untuk mengakses dokumen kontrak, BAP temuan audit, dan pelaporan pembinaan.

🏛️ 2. Validitas NIP & Satuan Kerja Resmi

Setiap akun ASN wajib terikat dengan NIP (Nomor Induk Pegawai) resmi dan terkunci pada OPD tertentu (Dinas PUPR, Disdik, Dinkes, Bappedalitbang, BPKAD, dsb).

⚖️ 3. Otorisasi Berjenjang (RBAC Kedinasan)

Peran akun (Super Admin, Admin Bidang, Eksekutif, Operator BUJK, Peserta TKK) ditentukan di awal oleh Super Admin DPU sesuai SK Penugasan Kepala Dinas.

📋 4. Jejak Audit Forensik Penuh

Riwayat siapa pejabat yang mengundang, kapan tautan diaktivasi, penyetelan sandi pertama, dan alamat IP login pertama kali tersimpan di basis data log sistem.

💡
Mode Hibrida Cerdas (Basis Data PostgreSQL + Persona Demo): Sistem SIJAKON dibangun dengan arsitektur hibrida berkeandalan tinggi. Apabila koneksi basis data PostgreSQL aktif, aplikasi terhubung langsung secara real-time dan menyajikan data produksi. Namun untuk kebutuhan evaluasi atau presentasi luring di depan pimpinan/auditor, mode persona 6-tier tetap tersedia dan dapat dialihkan secara instan tanpa mengganggu integritas database produksi.

Skema Database & Relasi Tabel (PostgreSQL Enterprise Engine)

Struktur 16 tabel relasional dari 5 modul migrasi SQL terstruktur

PostgreSQL 15

Database terstruktur dalam 5 file migrasi SQL bersih di folder prototype/supabase/migrations/, mengintegrasikan autentikasi, master data kedinasan, pengawasan SIMAK 3 pilar, dan sertifikasi TKK:

001_initial_schema.sql
Core Auth & Multi-OPD

Tabel opd, profiles, user_invitations, serta trigger otomatis sinkronisasi handle_new_user().

002_rls_policies.sql
Row Level Security (RLS)

Kebijakan isolasi multi-tenant OPD, hak akses peran SUPER_ADMIN, ADMIN_BIDANG, dan proteksi profil pengguna.

003_master_data_schema.sql
Master Data SIPJAKI

Tabel bujk, paket_pekerjaan (dengan koordinat Lat/Lng WebGIS & Kurva S), tkk, dan kecelakaan_kerja.

004_simak_pengawasan_schema.sql
SIMAK Pengawasan (3 Pilar)

Tabel pengawasan_sesi, pengawasan_item_pemeriksaan, pengawasan_rekomendasi, dan pengawasan_sdm_perencanaan.

005_pelatihan_tkk_schema.sql
Pelatihan & Sertifikasi (Pilar 5)

Tabel pelatihan_agenda, pelatihan_peserta, pelatihan_perencanaan, dan pelatihan_laporan.

Alur Pendaftaran & Aktivasi Akun (Opsi A)

Mekanisme berjenjang dari inisiasi Super Admin hingga pengguna menyetel sandi baru

Token Kedaluwarsa 7 Hari
1

Super Admin Mengisi Formulir Undangan di Dashboard

Super Admin DPU membuka menu Pengaturan > Manajemen Pengguna (/pengaturan/pengguna) dan menekan tombol "+ Undang Pengguna Baru". Modal formulir (src/components/admin/invite-user-modal.tsx) memuat input Nama Lengkap, NIP, Email Resmi, Nomor HP, Satuan Kerja (OPD), Tingkat Peran (Role), dan Sub-Spesialisasi (Variant).

Aktor: Super Admin DPU Komponen: src/components/admin/invite-user-modal.tsx
2

Sistem Men-generate Kriptografi Token & Simpan ke Basis Data

Sistem menghasilkan token kriptografi acak berkeamanan tinggi dengan format inv_xxxxxx dan menyimpannya di tabel public.user_invitations dengan status pending serta masa aktif 7 hari (expires_at = NOW() + INTERVAL '7 days').

Tabel: public.user_invitations Keamanan: One-Time Token (7 Hari)
3

Penerbitan Tautan Aktivasi Khusus

Tautan aktivasi khusus dibentuk secara otomatis dengan format:
https://sijakon.bogor.go.id/auth/set-password?token=inv_xxxxxx&email=pejabat@bogor.go.id.
Super Admin dapat menyalin tautan secara instan ke clipboard untuk dikirimkan melalui jalur kedinasan resmi (Email Dinas / WhatsApp Resmi).

Rute: /auth/set-password Kanal: Komunikasi Kedinasan Terenkripsi
4

Pengguna Membuka Halaman Aktivasi & Menyetel Kata Sandi Baru

Calon pengguna membuka tautan resmi di halaman /auth/set-password. Sistem memvalidasi token dan masa berlaku. Halaman menyajikan form penyetelan kata sandi dengan validasi keamanan minimal 8 karakter, konfirmasi pencocokan sandi, dan enkripsi tingkat tinggi.

Aktor: Calon Pengguna ASN / OPD Komponen: src/app/auth/set-password/page.tsx Syarat: Minimal 8 Karakter
5

Aktivasi Akun di Basis Data & Otomatis Masuk Dashboard

Setelah sandi tervalidasi, sistem memperbarui kredensial akun, menandai first_login: false pada public.profiles, dan mengubah status token undangan menjadi accepted. Pengguna langsung dialihkan ke Dashboard atau Portal mandiri sesuai peran yang dimilikinya.

Status: Profil Aktif (first_login = false) Redirect: /dashboard atau Portal Khusus
⚠️
Penanganan Undangan Kedaluwarsa (Expired Token): Apabila calon pengguna tidak menyetel sandi dalam kurun waktu 7 hari, token akan otomatis menjadi expired. Super Admin dapat menekan tombol "Kirim Ulang Undangan" di panel Manajemen Pengguna untuk memperpanjang token tanpa perlu menginput ulang biodata ASN.

Alur Login, Refresh Sesi JWT & Proteksi Rute SSR

Mekanisme autentikasi ganda yang aman, cepat, dan ramah simulasi

Next.js SSR Middleware

1. Halaman Login Resmi (/login)

Pengguna memasukkan Email Kedinasan dan Kata Sandi. Form dilengkapi dengan status lampu indikator koneksi basis data PostgreSQL secara real-time.

  • Indikator status: PostgreSQL (Live)
  • Modal pemulihan mandiri "Lupa Kata Sandi" via email
  • Quick-Switcher 6 Demo Persona untuk evaluasi offline

2. Verifikasi Kredensial Engine Auth

Mengirimkan permintaan ke modul Auth melalui supabase.auth.signInWithPassword().

  • Pencocokan hash password berstandar industri
  • Pengambilan profil lengkap dan relasi OPD via fetchSupabaseProfile()
  • Penerbitan Access Token (JWT) & Refresh Token otomatis

3. Next.js SSR Middleware (src/middleware.ts)

Setiap navigasi halaman di dashboard disaring oleh server middleware untuk menjamin proteksi penuh:

  • Memeriksa keabsahan cookie sesi JWT
  • Auto-refresh token jika mendekati masa kedaluwarsa
  • Pencegahan akses rute terlindungi tanpa autentikasi sah

Kebijakan Keamanan Row Level Security (RLS) PostgreSQL

Proteksi data di level engine PostgreSQL untuk mencegah manipulasi data

Zero Trust Architecture

Row Level Security (RLS) diaktifkan secara wajib pada seluruh tabel inti di PostgreSQL (berkas 002_rls_policies.sql). Hal ini menjamin bahwa meskipun ada upaya rekayasa pada kode antarmuka di sisi peramban, engine PostgreSQL tetap secara mutlak menolak pembacaan atau penulisan data yang tidak sah.

-- ============================================================================= -- 1. AKTIFKAN RLS PADA SELURUH TABEL INTI -- ============================================================================= ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE public.opd ENABLE ROW LEVEL SECURITY; ALTER TABLE public.user_invitations ENABLE ROW LEVEL SECURITY; -- ============================================================================= -- 2. KEBIJAKAN KEAMANAN: TABEL PROFILES -- ============================================================================= -- User dapat membaca profilnya sendiri CREATE POLICY "Users can view own profile" ON public.profiles FOR SELECT USING (auth.uid() = id); -- Super Admin dapat melihat semua profil pengguna CREATE POLICY "Super admin can view all profiles" ON public.profiles FOR SELECT USING ( EXISTS ( SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'SUPER_ADMIN' ) ); -- Admin Bidang dapat melihat profil pengguna dalam OPD yang sama CREATE POLICY "Admin bidang can view profiles in same OPD" ON public.profiles FOR SELECT USING ( EXISTS ( SELECT 1 FROM public.profiles p WHERE p.id = auth.uid() AND p.role IN ('SUPER_ADMIN', 'ADMIN_BIDANG') AND (p.opd_id = public.profiles.opd_id OR p.role = 'SUPER_ADMIN') ) ); -- Pengguna hanya boleh memperbarui profil sendiri tanpa dapat menaikkan hak akses (role) CREATE POLICY "Users can update own profile" ON public.profiles FOR UPDATE USING (auth.uid() = id) WITH CHECK ( auth.uid() = id AND role = (SELECT role FROM public.profiles WHERE id = auth.uid()) );

🔒 Penyimpanan Token Terenkripsi di Cookie

JWT Access Token dan Refresh Token disimpan pada cookie beratribut SameSite=Lax dan Secure untuk melindungi sesi pengguna secara mutlak dari risiko Cross-Site Scripting (XSS) dan CSRF.

🔄 Auto-Refresh Token di Latar Belakang

Sesi login diperbarui otomatis secara transparan oleh Next.js Server Middleware (src/middleware.ts) tanpa menginterupsi auditor saat sedang mengisi formulir checklist SIMAK di lapangan.
