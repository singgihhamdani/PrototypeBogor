Tata Kelola Akun Kedinasan (Mengapa Opsi A?)

Prinsip pendaftaran tertutup berbasis penugasan resmi SK Bupati / Kadis PUPR

Regulasi Akuntabel

Aplikasi SIJAKON Kabupaten Bogor mengelola dokumen hukum konstruksi yang sensitif, seperti Berita Acara Pemeriksaan (BAP SIMAK 1 & 2), Surat Rekomendasi Sanksi, serta data keuangan kontrak proyek OPD. Oleh karena itu, skema pendaftaran publik terbuka (self-registration) dilarang. Sistem mengadopsi Opsi A (Admin-Invited Registration) dengan landasan berikut:

🛡️ 1. Proteksi Data & Zero Spam

Mencegah pendaftaran akun anonim atau pihak yang tidak berhak mengakses dokumen kontrak dan pelaporan pembinaan jasa konstruksi.

🏛️ 2. Validitas NIP & OPD Resmi

Setiap akun wajib terikat dengan NIP (Nomor Induk Pegawai) ASN resmi dan terkunci pada OPD tertentu (Dinas PU, Disdik, Dinkes, dsb).

⚖️ 3. Otorisasi Berjenjang (RBAC)

Peran akun (Super Admin, Pembina Jasa, Tim Pengawas, OPD, Auditor) ditentukan di awal oleh Super Admin DPU sesuai SK Penugasan.

📋 4. Jejak Audit Lengkap

Riwayat siapa pejabat yang mengundang, kapan tautan diaktivasi, dan IP address login pertama kali tersimpan di log sistem.

💡
Mode Hibrida (Supabase Cloud + Persona Demo): Sistem SIJAKON dibangun dengan arsitektur hibrida cerdas. Apabila koneksi internet atau Supabase Cloud aktif, aplikasi menggunakan data riil cloud secara otomatis. Namun untuk kebutuhan presentasi luring (offline demo) di depan pimpinan/auditor, mode persona 6-tier tetap tersedia dan dapat dialihkan secara instan tanpa merusak data database.
🗄️

Alur Pendaftaran & Aktivasi Akun (Opsi A)

Mekanisme berjenjang dari inisiasi Super Admin hingga pengguna menyetel sandi baru

Token Kedaluwarsa 7 Hari
1

Super Admin Mengisi Formulir Undangan di Dashboard

Super Admin DPU membuka menu Pengaturan > Manajemen Pengguna (/pengaturan/pengguna) dan menekan tombol "+ Undang Pengguna Baru". Admin memasukkan Nama Lengkap, NIP, Email Kedinasan, Nomor HP, Satuan Kerja (OPD), dan Tingkat Peran (Role).

Aktor: Super Admin DPU Lokasi: src/components/admin/invite-user-modal.tsx
2

Sistem Men-generate Kriptografi Token & Simpan ke Supabase

Sistem membuat token acak berkeamanan tinggi sepanjang 64 karakter (UUID/SHA-256) dan menyimpannya di tabel public.user_invitations dengan status PENDING dan masa aktif 7 hari (expired_at = NOW() + INTERVAL '7 days').

Tabel: public.user_invitations Keamanan: One-Time Token
3

Pengiriman Undangan & Tautan Aktivasi

Tautan aktivasi khusus dibentuk dengan format:
https://sijakon.bogor.go.id/auth/set-password?token=INV-xxxxx&email=user@bogor.go.id.
Admin dapat menyalin tautan ini secara instan atau mengirimkannya otomatis ke email calon pejabat bersangkutan.

Rute: /auth/set-password Notifikasi Email / WA Kedinasan
4

Pengguna Membuka Halaman Aktivasi & Menyetel Kata Sandi Baru

Calon pengguna membuka tautan resmi. Sistem memvalidasi token di Supabase. Halaman menampilkan form aktivasi dengan indikator kekuatan kata sandi (Password Strength Meter) minimal 8 karakter, kombinasi huruf besar, angka, dan simbol.

Aktor: Calon Pengguna ASN / OPD Validasi: Minimal 8 Karakter
5

Aktivasi Akun di Supabase Auth & Otomatis Masuk Dashboard

Sistem mengeksekusi pendaftaran pengguna ke modul auth.users dan mengaktifkan data di public.profiles. Token undangan ditandai ACCEPTED. Pengguna langsung diarahkan ke Dashboard sesuai kewenangan perannya.

Status: Akun Aktif & Terverifikasi Redirect: /dashboard
⚠️
Penanganan Undangan Kedaluwarsa: Apabila calon pengguna tidak menyetel password dalam 7 hari, token akan otomatis menjadi EXPIRED. Super Admin dapat menekan tombol "Kirim Ulang Undangan" di tab Undangan Menunggu untuk memperpanjang token tanpa perlu menginput ulang data.

Alur Login, Refresh Sesi JWT & Proteksi Rute

Mekanisme autentikasi ganda yang aman, cepat, dan ramah simulasi

Next.js Middleware + SSR

1. Halaman Login Resmi (/login)

Pengguna memasukkan Email Kedinasan dan Kata Sandi. Form dilengkapi dengan status lampu indikator koneksi Supabase Cloud secara real-time.

  • Validasi format email domain dinas
  • Pilihan inline "Lupa Kata Sandi"
  • Pilihan cepat 6-Tier Demo Persona

2. Verifikasi Kredensial Supabase

Mengirimkan permintaan ke Supabase Auth melalui supabase.auth.signInWithPassword().

  • Pencocokan hash password (Argon2/Bcrypt)
  • Pengambilan data profil & OPD dari PostgreSQL
  • Penerbitan Access Token (JWT) & Refresh Token

3. Next.js Middleware (src/middleware.ts)

Setiap navigasi halaman di dashboard disaring oleh server middleware untuk menjamin proteksi penuh:

  • Memeriksa keabsahan cookie sesi JWT
  • Auto-refresh token jika mendekati masa habis
  • Mencegah akses rute terlindungi tanpa login

Contoh Cuplikan Logika Login Hibrida (src/lib/mock-auth.tsx):

const loginWithSupabase = async (email: string, password: string) => { const supabase = createClient(); const { data, error } = await supabase.auth.signInWithPassword({ email, password }); if (error) throw error; // Ambil profil lengkap dan Satuan Kerja (OPD) dari database const { data: profile } = await supabase .from("profiles") .select("*, opd:opd_id(id, nama_opd, singkatan)") .eq("id", data.user.id) .single(); setCurrentUser(profile); };

Kebijakan Keamanan Row Level Security (RLS)

Proteksi data di level engine PostgreSQL untuk mencegah manipulasi data

Zero Trust Architecture

Row Level Security (RLS) diaktifkan pada semua tabel di Supabase. Ini memastikan bahwa meskipun seseorang memodifikasi kode frontend di browser, PostgreSQL tetap menolak permintaan jika user ID atau role tidak sah.

-- 1. Mengaktifkan RLS pada seluruh tabel inti ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE public.user_invitations ENABLE ROW LEVEL SECURITY; ALTER TABLE public.opd ENABLE ROW LEVEL SECURITY; -- 2. Kebijakan: Pengguna hanya boleh melihat dan mengedit profil miliknya sendiri CREATE POLICY "Users can view their own profile" ON public.profiles FOR SELECT USING (auth.uid() = id); -- 3. Kebijakan: Super Admin DPU dapat mengelola semua pengguna CREATE POLICY "Super Admin can manage all profiles" ON public.profiles FOR ALL USING ( EXISTS ( SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'SUPER_ADMIN' ) );

🔒 Penyimpanan Token Terenkripsi

JWT disimpan pada cookie beratribut SameSite=Lax dan Secure untuk melindungi sesi pengguna dari serangan Cross-Site Scripting (XSS) dan CSRF.

🔄 Auto-Refresh Token Transparan

Sesi login diperbarui otomatis di latar belakang oleh Next.js Server Middleware tanpa menginterupsi pengguna saat sedang mengisi checklist pengawasan.
